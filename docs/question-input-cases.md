# 질문함의 터미널 비동기 질문 응답 회귀 계획

대상: `fix/desktop-1.3.1-question-input`, 기준 `6e453bf86a499584731022db8e60390e1aa3306c`.
요구: 질문함에서 질문을 읽을 수 있는 살아 있는 터미널 세션이면, GUI 대화 보기로 전환하지 않고 해당 비동기 질문에 직접 답변한다. 운영 대화·인증·서비스는 사용하지 않는다.

| ID | 입력·사전조건 | 절차 | 기대 결과·합격 기준 | 실제 결과 |
| --- | --- | --- | --- | --- |
| QI-01 | GUI 입력 소유권 없는 터미널, 신선하고 완전한 비동기 질문 관측 | 질문함 목록 조회 후 한글 답변 전송 | 입력 가능, 원래 thread/turn/question ID로 정확히 1회 전달, GUI 소유권과 터미널 보기 불변 | NOT_RUN |
| QI-02 | QI-01의 질문, 답변 전송 중 또는 접수 결과 불명 | 같은 질문 재전송·목록 새로고침 | 중복 전송 없음, 불명 결과를 성공·해결로 표시하지 않음 | NOT_RUN |
| QI-03 | 연결 끊김·불완전 질문 이력·종료·다른 작업·해결된 질문 | 답변 시도 또는 대기 중 상태 변경 | 전송 전 재검증, 잘못된 대화/작업으로 무전송, 마지막 질문 원문 보존 | NOT_RUN |
| QI-04 | 터미널과 GUI의 입력 소유권 전환 또는 압축 요청 경합 | 답변 대기 중 전환/압축 요청 | 기존 상한과 순서 보존, 동시 writer 없음, 원치 않는 보기 전환 없음 | NOT_RUN |
| QI-05 | GUI가 소유한 질문·기존 승인 요청·미지원 공식 CLI | 기존 응답과 질문함 조회 | 기존 응답 경로 보존, 다른 연결이 소유한 일반 RPC 승인에는 답변을 위조하지 않음 | NOT_RUN |
| QI-06 | 질문함의 응답 가능한 비동기 질문, 화면 폴링 | 키보드로 한글 입력·전송, 전송 직후 재클릭 | 입력/초안 유지, 응답 IPC 1회, 원래 세션 열기/화면 전환 호출 없음 | NOT_RUN |

Rust 기존 runner의 실제 RPC fixture와 Playwright 질문함 fixture를 사용한다. backend 원인을 겨냥한 동일 native 시험의 수정 전 실패/수정 후 성공을 CI에서 확인한다. UI 합성 시험은 실제 CLI·모델·운영 GUI의 검증으로 확대하지 않는다. 실패 출력과 후보 커밋을 보존하고, 전체 CI의 실제 결과를 별도 검증 자료에 기록한다.
