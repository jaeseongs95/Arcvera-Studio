## 실행 파일과 공유 서버

[Releases](https://github.com/jaeseongs95/Arcvera-Studio/releases)에서 포터블 ZIP이나
사용자 단위 설치 파일을 내려받으세요. Windows x64와 WebView2가 필요하며,
실행 파일은 서명되지 않았습니다.
포터블 ZIP 전체를 압축 해제한 뒤 `arcvera-studio.exe`를 실행하세요.
Desktop이 작업 프로세스를 직접 실행하고 Windows Job으로 소유·정리하므로 별도 Desktop
helper 실행 파일은 필요하지 않습니다. Codex·셸·WebView2는 별도 프로세스로 실행됩니다.

먼저 Arcvera Core를 별도로 설치하고 로그인하세요. 공식 Codex CLI는 지원하지 않습니다.
데스크톱 배포물에는 CLI 실행 파일이 없으며 앱이 이를 내려받지도 않습니다. 오른쪽 위
**⚙ 설정 → 실행 파일 설정**에서 네이티브 `codex.exe`를 선택하면
새 세션과 세션 조회에 사용할 경로가 저장됩니다.
저장한 경로·실제 적용 경로·찾은 위치를 확인할 수 있습니다.
파일 선택을 취소하면 기존 설정을 유지하고, 경로를 바꿔도 열린 터미널은 유지합니다.

설치된 `opendiy-codex-launcher.exe`도 선택할 수 있습니다. 새 요청마다 런처가 선택한 패키지를
확인해 CLI와 자동 서버 후보를 함께 사용합니다. 열린 세션은 시작할 때 확정한 경로를 유지합니다.
직접 지정한 서버는 그대로 사용하며, 런처 조회가 실패하면 다른 실행 파일로 대체하지 않고 오류를 알립니다.

**자동 찾기**는 앱에 저장한 경로를 지우고 `ARCVERA_STUDIO_CODEX` 환경변수(없으면 기존 `AGENT_GRID_CODEX`),
`PATH` 순서로 실행 파일을 찾습니다. 직접 저장한 경로가 가장 우선합니다.
경로가 잘못되면 오류를 표시하며 다른 실행 파일로 몰래 대체하지 않습니다.
CLI는 `--remote`와 공유 서버·프록시 명령을 지원해야 합니다.
공유 연결을 지원하는 CLI에서 접속에 실패하면 원인을 표시하며 개별 서버로 몰래 대체하지 않습니다.

**Arcvera Core 1.x 정식 CLI와 앱 서버만 지원합니다.** 공유 서버의 `daemon`·`proxy` 명령과 보호된 `--existing-installation`·`--first-installation` 시작 옵션이 필요합니다. 공식 Codex CLI와 개별 서버 실행은 지원하지 않습니다. 기존 설정·인증·대화를 삭제하지 않으며, 이전 공식 CLI 사용자는 **실행 파일 설정**에서 Core 패키지를 선택해야 합니다. 확장 기능과 예약 제어는 CLI와 연결된 서버의 실제 지원 여부를 확인합니다.

기존 daemon 데이터는 보존합니다. 서버 패키지를 직접 선택하기 전에 다른 Codex 창과 모바일의 작업을 마치세요. 버전 번호만으로 기능 지원을 추정하지 않고 실제 선언을 확인합니다.

**설정 → 실행 파일 설정**에서 CLI를 선택하며 앱 서버의 별도 지정은 선택 사항입니다. 서버 자동 선택은 CLI와 같은 폴더의 `codex-app-server.exe`를 사용하고, 그 파일이 없을 때 같은 Core CLI의 app-server 명령을 검사합니다. CLI 선택만 바꾸면 열린 터미널을 유지합니다. 앱 서버 파일을 직접 선택하면 패키지·소유권 검사를 통과한 경우 관리 서버를 교체하며, 같은 경로를 다시 선택해도 교체를 요청합니다. 유휴 대화는 같은 대화·작업 경로로 다시 연결하고 일반 대화 초안과 보기를 복원합니다. 진행 작업·대기 중이거나 결과가 불명인 요청·첨부·보존 여부를 확인할 수 없는 터미널 입력이 있으면 교체를 거부합니다. 작업을 마친 뒤 해당 세션을 직접 종료하고 서버를 다시 선택하세요. 선택 취소나 잘못된 파일은 기존 실행 환경을 유지합니다. 전환이나 재연결 실패·결과 불명은 초안과 복구 정보를 남기며 서버 교체·모델 요청을 자동으로 재시도하지 않습니다. CLI와 연결된 서버는 각각 Core 1.x 정식 버전이어야 합니다. 각 연결은 빌드 메타데이터를 포함한 실제 서버의 검증된 전체 버전을 Core 초기화 계약에 전달합니다. 초기화 계약이 없거나 서버 버전과 일치하지 않으면 해당 연결을 거부합니다. 다른 서버 패키지를 선택할 때는 아래의 별도 교체 검사를 거칩니다. 처음 설치할 때는 선택한 CLI의 준비 절차를 사용하고, 기존 서버를 자동으로 교체하지 않습니다.

구조화 대화·서브에이전트·수동 압축 버튼은 각 기능의 실제 지원 선언에 따라 표시합니다. 예약 버튼은 Desktop에 저장한 정의를 관리하기 위해 CLI 지원 여부와 관계없이 표시하며, CLI 등록·실행 제어는 지원과 연결 상태를 확인한 뒤 허용합니다. 기능 지원과 연결·작업 준비 상태는 따로 확인합니다. 대화 화면 연결이 실패하면 안전하게 입력 소유권을 해제한 뒤 터미널로 돌아가며, 해제 결과가 불명확하면 작성 중인 내용과 입력 소유권을 보존합니다.

**서버 버전 확인 → 버전 맞추기…**는 전체 패키지를 검토한 뒤 다른 Codex 창과 모바일의 작업이 끝났다는 확인을 받습니다. 작업을 강제로 종료하지 않는 갱신을 CLI가 지원해야 하며 해당 선언이 없는 실행 환경에서는 실행할 수 없습니다. 공유서버는 관리용 CLI를 통해 실행되므로 선택한 독립 서버 파일과 관리 CLI의 실행 경로가 다를 수 있습니다. 전환 성공과 실제 연결 확인이 끝나야 자동 복원을 재개합니다. 결과가 불명확하면 자동 재연결·재시도를 막으므로 상태를 다시 확인한 뒤 직접 재시도하세요. 이미 보낸 종료 요청은 취소할 수 없고 나중에 완료될 수 있습니다. 모든 updater 프로세스의 종료를 보장하는 기능은 아닙니다.

과거 배포 조합의 시험 기록은 Git 이력에 보존하며, 이 배포판의 지원 근거로 사용하지 않습니다.

공유 서버 준비는 `--existing-installation`과 `--first-installation` 보호 옵션을 확인하며, `daemon` 명령이 있다는 사실만으로 지원을 판단하지 않습니다.

## 프로젝트와 터미널

**프로젝트 가져오기**에서 Windows 기본 폴더 선택창(`IFileOpenDialog`)으로 기존 로컬
폴더를 선택하세요. 가져온 프로젝트는 터미널이 종료되어도 사이드바에 남습니다.
해당 프로젝트의 세션 불러오기 팝업에서 기존 대화를 선택하거나,
작업 경로가 채워진 새 세션을 시작할 수 있습니다.

**새 프로젝트**는 이름을 가진 세션 묶음을 만들며, 기존 기본 실행 폴더는 선택 사항입니다.
디스크에 새 폴더를 만들지는 않습니다. 프로젝트 옆 **⋯**에서 이름을 바꾸거나
즐겨찾기로 지정하고 삭제할 수 있습니다. 삭제는 앱의 프로젝트 메타데이터만 지우고
소속 세션을 **미분류**로 옮깁니다. 실행 중인 터미널·원본 대화·디스크 폴더는 보존합니다.
세션의 **프로젝트로 이동**도 소속만 바꾸며 터미널을 다시 시작하거나 실제 실행 폴더를
바꾸지 않습니다.

격자 위 프로젝트 탭이나 사이드바에서 프로젝트를 선택하면 해당 프로젝트의
열린 세션을 볼 수 있습니다. **전체**는 모든 세션을 표시합니다.
탭을 전환해도 터미널 실행과 출력을 유지하며, 프로젝트 전환이나 세션 이동 뒤에는
최신 출력 위치를 표시합니다. 세션 이동 단축키는 현재 보이는 프로젝트에
적용됩니다. 선택한 프로젝트에 기본 폴더가 있으면
새 세션·세션 불러오기도 그 경로에서 시작합니다.

다른 프로젝트나 **전체**로 전환하면 표시 대상인 터미널과 대화 보기가 최신 출력·마지막
메시지로 이동합니다. 이미 화면에 보이던 카드에도 적용됩니다. 같은 프로젝트를 다시
선택할 때는 읽던 위치를 유지합니다. 전환해도 대화 초안을 유지하며, 프로젝트 탭으로
전환한 경우 선택한 탭의 초점을 빼앗지 않습니다.

**세션 불러오기**는 좌우로 나뉜 팝업입니다. 왼쪽에서 제목을 검색하고 프로젝트로
필터링한 뒤, 오른쪽에서 날짜·대화 ID·최근 대화를 확인하세요.
이미 열린 대화는 기존 터미널로 이동합니다. 조회는 앱이 소유한 프록시를 통해
공유 Core 서버에 읽기 전용 요청을 보냅니다. 공유 서버에 연결할 수 없으면
개별 서버를 실행하지 않고 오류를 표시합니다.
최근 대화는 정해진 크기로 나눠 읽으며 앱 데이터베이스에 복사하지 않습니다.

**새 세션**에서는 경로를 직접 입력할 수도 있습니다. 모델 선택·로그인·권한 응답은
Core CLI 화면에서 처리하세요. 제어할 터미널에 직접 입력하세요.
CLI 입력창에서 **Shift+Enter**로 줄바꿈할 수 있습니다.

왼쪽 목록에서 등록된 프로젝트를 드래그하거나 **⋯ → 위로 이동 / 아래로 이동**으로 순서를 바꿀 수 있습니다. 순서는 저장되어 앱을 다시 열어도 유지되며, 프로젝트 탭과 이동 대상 목록에도 함께 반영됩니다. 즐겨찾기 상단 배치는 유지하고 같은 그룹 안에서 이동합니다. 목록 순서만 바뀌며, 저장에 실패하면 기존 표시 순서를 유지합니다.

## 기록·복원·재시작

앱을 완전히 종료했다가 다시 실행하면 종료 직전에 열려 있던 작업 공간을 복원합니다.
실행 중이던 세션은 저장된 대화 ID로 다시 연결하며 제목·프로젝트·격자 순서와 크기를
유지합니다. 이전 입력을 다시 보내거나 저장된 터미널 대화록 전체를 적재하지 않습니다.
개별로 닫은 세션은 다시 열지 않습니다.

대화 ID가 없거나 이미 종료한 세션, 이전 버전에서 실행 의도 없이 저장한 항목은
자동으로 새 대화를 만들지 않습니다. 연결하지 못한 항목은 저장된 세션 목록에 남아
직접 다시 시도할 수 있습니다. 일부 연결이 실패해도 나머지 저장 항목을 지우지 않습니다.
창의 닫기 버튼으로 트레이에 숨겼다가 다시 여는 경우에는 실행 중인 터미널을 그대로 사용합니다.

실행하지 않는 저장 항목은 동시 실행 개수에 포함하지 않습니다. 실제 터미널은 기존
32개 자원 상한을 유지하며, 자동 복원이 이 상한에 도달하면 남은 항목은 저장 목록에 둡니다.

세션 상단의 원형 화살표 **세션 재시작**을 누르면 해당 세션의 실행 프로세스를 종료하고 같은 대화를 다시 연결합니다. 대화 ID·프로젝트·격자 위치를 유지하며, 확인 후 실행 중인 작업을 중단합니다. 미전송 초안과 첨부는 먼저 정리하세요. 대화 ID가 확인되기 전에는 재시작할 수 없고, 종료가 확인되지 않으면 다른 프로세스를 시작하지 않습니다. 재연결에 실패해도 원래 대화는 유지되어 다시 시도할 수 있습니다.

## 대화 보기와 질문함

세션 카드의 **대화 / 터미널** 버튼으로 같은 대화의 보기를 전환합니다. 기존 터미널 격자는
유지되며, 보기 전환으로 새 대화를 만들거나 이전 입력을 다시 보내지 않습니다. 대화
보기는 실행 기반의 구조화된 이력을 페이지로 읽고 최근 이벤트를 반영합니다. 오래된
구간과 큰 원문은 필요할 때 조회하며 터미널 문자열을 메시지로 변환하지 않습니다.

대화 보기에는 수동 구독과 유휴 상태 입력을 지원하는 실행 기반이 필요합니다.
CLI만 새로 선택해도 이미 실행 중인 공유 서버의 버전이 자동으로 바뀌지는 않습니다. 앱 서버 파일을 직접 선택하면 앞서 설명한 교체 검사를 적용합니다.
대화 보기는 실제 연결한 서버의 지원 여부를 확인하며, 보기 전환 자체가 서버를 중단하거나 교체하지 않습니다.
서버 버전을 맞추려면 실행 파일 설정의 별도 확인 절차를 사용하세요.
구형 서버에서는 기능 제한을 안내하며, 보기 전환으로 대기 작업을 실행하거나 진행 중인
작업에 새 입력을 합칠 수 있는 이전 방식으로 대체하지 않습니다. 기존 터미널 보기는
유지됩니다. 주간 사용량도 기존 공유 서버로만 조회하며, 서버를 사용할 수 없으면
마지막으로 확인한 값과 조회 시각을 유지합니다.

표시 구간 검색은 현재 화면에 있는 메시지·미리보기만 대상으로 하며 전체 대화를 불러오지 않습니다. 일치 메시지 사이를 이동하거나 최신 구간으로 돌아갈 수 있고, 메시지 복사는 현재 표시된 본문만 복사합니다. 큰 원문의 다른 구간은 직접 조회해야 검색·복사에 포함됩니다.

작성창은 여러 줄과 한글 조합, 이미지 붙여넣기, 파일 선택을 지원합니다. 일반 파일은
로컬 파일 참조이며 ChatGPT의 문서 업로드 서비스와 동일한 기능이 아닙니다. 모델과
추론 수준은 실행 기반이 알려준 값과 선택 가능한 목록을 사용합니다. 확인하지 못한
값은 미확인으로 표시합니다. 실행 기반이 지원하지 않는 기능은 오류나 제한으로 표시합니다.
전송 결과가 불명확하면 자동으로 다시 보내지 않고 초안을 보존합니다.
터미널로 돌아가려는 명시적인 전환은 일반 미응답 요청을 남긴 채 입력을 인계할 수 있습니다.
응답 처리 중이거나 전송 결과·요청 소유권을 확인하지 못한 경우에는 전환을 거절하고
대화 화면과 초안을 유지합니다. 창 숨김이나 연결 정리는 이 입력 인계를 대신 실행하지 않습니다.
이력을 조회하는 동안 새 이벤트가 도착하면 늦은 응답으로 최신 내용을 덮어쓰지 않고
다시 조회하도록 안내합니다. 이력 조회 불가를 빈 대화나 유휴 상태로 처리하지 않습니다.

우측 상단 **질문함**은 확인된 미응답 질문·승인 요청의 건수를 보여줍니다. 질문함을
열어도 건수는 초기화되지 않으며, 서버에서 해결됐음을 확인하면 줄어듭니다. 원문을
수집한 비동기 질문은 터미널 보기를 유지한 채 질문함에서 직접 응답할 수 있습니다.
현재 질문과 연결 상태를 확인할 수 없거나 다른 연결이 소유한 일반 승인 요청은
원래 세션에서 확인합니다. 질문 원문을
조회할 수 없는 응답 대기 상태는 별도 안내와 원래 세션으로 이동하는 기능을
제공합니다. 이 상태를 확인된 질문 수로 계산하지 않습니다.

전송한 붙여넣기 이미지는 이후 대화 재개에 필요할 수 있어 앱 소유 저장소에 보존합니다.
미전송 임시 파일은 정리하고 사용자 원본은 삭제하지 않습니다. 저장소 예산을 넘으면
이전 첨부를 자동 삭제하는 대신 새 첨부를 거부합니다.

## 플러그인과 스킬

오른쪽 위 **⚙ 설정 → 플러그인·스킬·Hook**을 열면 실행 파일 설정에서 선택한 CLI와 현재 프로젝트를
기준으로 관리합니다. 기본 플러그인 화면에는 설치된 항목을 표시하며 사용 설정과 제거를
관리할 수 있습니다. 새 항목은 **플러그인 추가**에서 이름을 두 글자 이상 입력하고 **찾기**를
누르세요. 이 화면을 열기만 해서는 전체 카탈로그를 가져오지 않으며, 직접 검색해야
카탈로그에서 일치하는 미설치 항목을 보여줍니다. 설치 대상을 검토·확인한 뒤 설치가
확인되면 설치된 항목 관리로 돌아옵니다. 검색·설치 실패도 표시합니다.

마켓플레이스 소스와 스킬 사용 설정도 관리할 수 있습니다. `SKILL.md`가 들어 있는
로컬 스킬 폴더를 Windows 기본 폴더 선택창으로 골라 현재 프로젝트나 사용자 스킬
폴더로 가져올 수 있습니다.
적용 전 검토 화면에서 실제 대상과 범위를 확인합니다. 기존 폴더를 덮어쓰지 않으며,
링크나 크기 제한을 넘는 폴더는 거부합니다. CLI가 지원하지 않는 기능과 오류도 표시합니다.

플러그인·마켓플레이스는 CLI 명령으로, 스킬·설정은 app-server API로 실제 반영하고
결과를 다시 조회합니다. CLI 인증과 설정은 해당 CLI가 관리합니다. 변경된 확장 기능은
새 세션에서 사용하며, 실행 중인 터미널을 강제로 재시작하지 않습니다.

## Hook

**⚙ 설정 → 플러그인·스킬·Hook → Hook**을 엽니다. 선택한 CLI와 프로젝트를 기준으로
목록을 조회하며, 항목을 선택하면 이벤트·출처·처리 방식·사용 여부·신뢰 상태를 확인할 수
있습니다. API 미지원이나 구성 오류·조회 실패는 빈 목록과 구분해 표시합니다.

사용 설정을 바꾸거나 신뢰를 승인하기 전에 정확한 대상을 검토하세요. 변경은 선택한 CLI의
사용자 설정에 저장되므로 다른 프로젝트에도 영향을 줄 수 있습니다. 쓰기 전에 현재 내용의
지문과 설정 버전을 확인하고, 변경 후 실제 상태를 다시 조회합니다. 정의가 바뀌었거나
관리 정책이 적용된 Hook, 버전 충돌은 덮어쓰지 않습니다. 실패하거나 결과를 확인하지 못한
변경은 자동으로 다시 요청하지 않습니다.

새 신뢰 승인은 화면에서 실행 내용을 검토할 수 있는 command Hook에만 제공합니다.
MCP·prompt·agent Hook은 조회 메타데이터에 실행 정의 일부가 없어 이 화면에서 새로 신뢰를
승인할 수 없습니다. 정책이 허용하면 미신뢰 Hook을 비활성화하거나 이미 신뢰된 Hook의
사용 설정을 바꿀 수 있습니다. command Hook의 신뢰 승인은 현재 내용 지문만 승인하며
자동으로 활성화하지 않습니다. 이 화면은 Hook 정의를 만들거나 시험 실행하지 않습니다.
바뀐 구성은 새 세션에서 확인하세요. 상태 재조회 성공만으로 실행 중인 모든 대화가 구성을
다시 읽었다고 판단하지 않습니다.

## 서브에이전트

실행 중인 세션 상단의 **서브에이전트 관리** 아이콘에서 해당 세션의 직접 하위
에이전트를 확인합니다. 상단 요약은 현재 불러온 페이지의 상태별 개수입니다.
왼쪽에서 검색과 상태 필터를 조합하고, 오른쪽에서 상태·역할·모델·추론 수준을 확인합니다.
작업 제어, 메시지 전송, 영구 삭제를 구분된 영역에서 사용할 수 있습니다.
지시 전송·현재 작업 중단·종료·재개를 요청할 수 있습니다.
종료는 하위 작업도 중단하므로 한 번 더 확인하며 저장된 대화는 삭제하지 않습니다.

**에이전트 삭제…**는 서버의 읽기 전용 `thread/cleanupCompleted` 미리보기로
삭제 가능 여부를 먼저 확인합니다. 영구 삭제를 확인해야 선택한 한 에이전트의 미리보기
정보만 서버에 전달하며 복구할 수 없습니다. 실행·대기·미확인 상태는 보호하고,
서버도 상태가 바뀐 에이전트, 하위 에이전트·대기 작업·참조·미완료 목표가 있는 항목을
보존합니다. 하위 에이전트가 있으면 삭제 가능한 하위 항목부터 개별 삭제합니다.
관리 기능을 지원하는 이전 서버라도 삭제 API는 지원하지 않을 수 있습니다.
삭제 확인 중에는 자동 갱신을 멈춥니다. 선택 변경·수동 갱신·창 숨김은 확인을 취소합니다.
팝업을 열거나 삭제 가능 여부를 조회하는 것만으로는 삭제하지 않습니다.

이 기능에는 연결된 서버의 `supportsSubagentManagement` 선언이 필요합니다.
미지원 실행 파일에서는 관리 요청을 보내지 않습니다. 목록은 한 번에 100개씩 조회하고
팝업이 보일 때만 5초 간격으로 갱신하며 대화 본문은 가져오지 않습니다. 응답이 유실된
변경은 자동 재전송하지 않고 기존 관리 명령의 원래 요청 처리 여부를 다시 확인합니다.
삭제 API에는 요청 ID로 결과를 재확인하는 기능이 없어 삭제 응답이 유실되면 그 연결의
새 변경을 차단합니다. 목록과 서버 상태를 확인하고, 확인이 끝나지 않으면 세션을 다시
연결하세요. 한 페이지에서 항목이 보이지 않는다는 사실만으로 삭제 성공을 판단하지 않습니다.

선택한 CLI가 최신이어도 이미 실행 중인 공유 서버가 이 기능을 지원하지 않으면 사용할 수
없습니다. 실행 파일을 선택하거나 앱만 다시 시작해도 그 서버는 업데이트되지 않습니다.
서버 갱신은 진행 중인 작업을 중단할 수 있으므로 작업을 마친 뒤 호환 배포물의 갱신 절차를
따르세요. 앱은 이 작업을 자동으로 실행하지 않습니다.

## 컨텍스트와 압축

세션 상단에서 컨텍스트 사용량과 수동 압축 버튼을 확인할 수 있습니다. 표시 비율은
서버가 보고한 최근 모델 응답의 토큰 사용량을 컨텍스트 창 크기로 나눈 값입니다.
누적 과금 사용량이나 터미널 대화록 크기가 아닙니다. 아이콘에 마우스를 올리면
토큰 수를 확인하고, 클릭하면 새로고침하며 지원되는 경우 해당 세션의 설정을 엽니다.
누락되거나 오래된 측정값은 —로 표시합니다.
보이는 세션만 2초마다 작은 로컬 상태 하나를 읽으며 숨긴 세션은 조회를 멈춥니다.

서버가 지원을 확인한 경우 사용량 아이콘을 누르면 그 카드의 대화를 대상으로 **세션 컨텍스트
크기**를 엽니다. 양의 정수로 토큰 수를 입력해 **적용**하거나 **기본값 복원**으로 해당 세션의
지정값을 해제하세요. 요청값과 실효 예산은 따로 표시하며 모델 한도에 따라 실효 예산이 더
작을 수 있습니다. 변경은 해당 세션의 다음 turn부터 적용됩니다. 다른 세션·전역 기본값은
바꾸지 않으며 모델이 지원하는 한도를 늘리지 않습니다. 미지원이나 확인되지 않은 응답에서는
크기 조절을 제공하지 않고 기존 사용량 새로고침을 유지합니다.

서버가 요청값과 일치하는 적용 응답을 보내야 변경을 확인합니다. 창을 닫아도 이미 보낸
요청이 취소되지는 않습니다. 결과가 불명확하면 자동으로 다시 보내지 않으므로 아이콘을
눌러 상태를 다시 확인하세요. 원래 요청값의 적용 여부를 확인하지 못하면 그 세션의 추가
크기 변경은 계속 제한합니다. 재시작·재개 후 지정값이 유지되는지는 실행 환경의 확인 없이
가정하지 않습니다.

수동 압축 버튼은 압축만 요청하며 현재 터미널/대화 보기와 입력 소유권을 바꾸지 않습니다.
같은 대화의 기존 연결에서 진행 중 작업·승인 대기·결과 미확인이 없을 때만
요청합니다. 실행 중 작업을 대체할 수 있는 기존 압축 명령으로 우회하지 않으며,
원자적으로 유휴 상태를 확인하는 기능이 없는 실행 환경에서는 압축을 제한합니다.
요청 접수와 완료를 구분하고 결과가 불명확하면 자동으로 재요청하지 않습니다.
작성 중인 초안과 원래 대화는 보존합니다.

<a id="schedules"></a>

## 세션 예약

세션 상단의 시계 아이콘에서 **현재 CLI 예약**과 **Desktop 저장 정의**를 관리합니다. 전체 작업 원문과 반복 간격 또는 한 번 실행할 현지 시각을 작성하고 **정의만 저장**하거나 **저장 후 CLI 등록**을 누릅니다. 저장 정의는 앱의 전용 데이터베이스에 남아 CLI 종료나 Desktop 재시작 뒤에도 조회·편집할 수 있습니다. 대화 식별자가 아직 확인되지 않은 세션에서는 먼저 대화를 시작해야 저장할 수 있습니다.

CLI가 종료되면 실행 예약은 끝납니다. 같은 대화를 다시 시작한 뒤 저장 정의의 **이 CLI에 수동 등록**을 눌러 다시 등록하세요. 다른 대화에 정의를 옮기거나 자동 등록하지 않으며, 별도 운영체제 예약이나 실행기를 만들지 않습니다. 시각이 지난 일회성 정의는 **새 실행 시각 지정**으로 미래 시각을 저장해야 등록할 수 있습니다. CLI에서만 만든 예약은 목록에 원문 대신 미리보기만 제공되므로 저장 정의로 가져올 수 없습니다.

**저장 정의 삭제**는 전체 원문과 일정을 Desktop에서 삭제합니다. CLI에 이미 등록한 예약은 유지됩니다. **예약 삭제**는 현재 CLI의 실행 예약만 지우고 저장 정의는 유지합니다. 같은 CLI에 이미 등록한 정의는 다시 등록할 수 없습니다. 등록 결과가 불명확하면 새로고침으로 원래 요청을 확인하며 자동 재전송하지 않습니다. 원래 등록의 job 식별자를 확정할 수 없는 정의는 해당 CLI가 종료될 때까지 재등록과 편집·삭제를 제한합니다.

예약 삭제와 일시정지는 이미 실행 중인 회차를 중단하지 않습니다. 현재 회차 중단은 해당 예약이 시작한 작업만 대상으로 하며 반복 예약은 유지합니다. 결과가 불명확한 요청은 자동 재전송하지 않고 처리 여부가 확인될 때까지 변경을 제한합니다. 구조화 예약 제어를 지원하지 않는 CLI에서는 미지원 안내와 함께 변경 기능을 제한합니다.

## 모바일 원격 제어

오른쪽 위 **⚙ 설정 → 모바일 원격 제어**에서 실행 중인 세션을 선택하고 상태를 조회하세요.
원격 제어를 켜고 상태를 새로고침해 원격 서비스 연결을 확인한 뒤,
연결 코드를 만들어 모바일 Codex에 입력합니다. 원격 서비스 연결됨은 세션 서버가
중계 서비스에 연결됐다는 뜻이며, 실제 휴대전화 연결 여부와는 별개입니다.

선택한 CLI는 원격 제어 app-server API를 지원하며 ChatGPT 계정으로 로그인해야 합니다.
API 키 로그인은 지원하지 않습니다. 공유 서버를 지원하는 CLI에서는 기본 프록시를 통해
터미널·상태 관측·모바일 관리가 같은 기존 서버에 연결됩니다. 켜기·끄기와 연결 코드는
그 서버의 모든 대화에 적용됩니다. 앱 시작 시 실행 중인 공유 서버를 재사용하거나
설치된 서버를 먼저 시작하고, 연결을 확인한 뒤 세션을 복원합니다. 시작에 실패하면
저장된 세션을 유지하며 다시 시도할 수 있습니다. 시작 과정에서 공유 서버를 교체하거나 종료하지 않습니다.
서버를 바꾸려면 **실행 파일 설정**에서 앱 서버 파일을 직접 선택하거나, **서버 버전 확인 → 버전 맞추기…**의 별도 확인 절차를 사용하세요.
Core 시작에는 `--existing-installation`과 보호된 `--first-installation` 옵션을
사용합니다. 보호 옵션이 없으면 개별 서버로 우회하지 않고 미지원을 안내합니다.

공유 세션 종료는 터미널을 닫기 전에 원래 작업 ID를 고정해 그 작업만 중단합니다.
늦게 시작한 모바일 작업으로 대상을 바꾸지 않습니다. 중단 결과가 불명이면 알 수 없음으로
남기고 자동 재전송하지 않습니다. 앱을 종료해도 공유 서버와 기존 원격 등록은 유지됩니다.
일반 종료가 중단 미확인으로 실패해도 로컬 자원이 모두 회수됐다면, 경고를 확인한 뒤
**중단 미확인 상태로 앱 닫기**를 따로 선택할 수 있습니다. 원격 작업이 계속 실행될 수 있으며,
이 선택은 작업 상태를 중단됨으로 바꾸거나 중단 요청을 다시 보내지 않습니다.
연결 코드는 저장하지 않으며 실제 휴대전화 연결과 제어는 아직 검증하지 않았습니다.
공유 연결에는 같은 패키지의 Core CLI·서버를 사용합니다. 실행 파일과 체크섬은
릴리스 노트에서 확인하세요. 초기 이력을 아직 조회할 수 없다는 경고가 있어도 살아 있는
세션의 입력은 유지됩니다. 이 경고를 과거 대화 전체가 불러와졌다는 뜻으로 해석하지 마세요.

## 주간 사용량

왼쪽 아래 표시기는 선택한 CLI 계정의 대표 사용 한도 중 기간이 명시적으로 10,080분인
주간 구간에서 사용 비율과 제공되는 초기화 시각을 읽습니다. 이 앱의 세션 사용량을
합산한 값이 아닌 계정 사용량입니다. 주간 정보 미제공과 조회 실패를 구분하며
0%로 처리하지 않습니다. 이전 조회가 끝난 뒤 1분마다 자동으로 조회하며, 창이 숨겨진
동안에는 멈춥니다. 새로고침 버튼으로 즉시 다시 조회할 수 있고, 수동 조회는 5초 간격으로
한 번에 하나씩 실행합니다. 실패하면 마지막 정상값과 조회 시각을 유지하며 기술 오류는
사용량 화면에 표시하지 않습니다. 외부 세션 기록은 설정에서 확인할 수 있습니다.

## 호환성과 첨부 저장 공간

**설정 → 실행 파일 설정 → 호환성 확인**은 선택한 실행 파일의 버전·도움말만 새로 조회합니다. 서버 연결을 만들거나 `daemon version`을 호출하지 않습니다. 서버 버전과 기능 선언은 같은 실행 파일·소켓의 기존 세션이 이미 받은 정보만 재사용하며, 현재 실행·연결 상태를 재확인한 값은 아닙니다. 관측하지 못한 버전·기능과 안전하게 확인할 수 없는 다음 시작 선택값·실제 서버 경로는 미확인으로 표시합니다. 압축 지원도 이 조회에서는 미확인입니다. 세션 재개나 서버 설치·시작·교체는 하지 않으며, 실제 기능 실행 시에는 연결·권한·작업 상태를 따로 검사합니다.

**설정 → 첨부 저장 공간**에서 앱이 보관한 이미지 용량과 상한, 현재 실행의 미전송 초안·보존 이미지·이전 실행 등을 구분해 봅니다. 원본 로컬 파일은 집계하지 않습니다. 초안은 원래 세션에서 첨부를 제거해 정리하며, 전송됐거나 결과가 불명확한 이미지와 소유 상태를 확인할 수 없는 파일은 보존합니다.

## Codex와 데이터

기존 로그인과 `CODEX_HOME`을 사용합니다. 최초 CLI 설치와 로그인은 별도이며 전역 권한 설정을 바꾸지 않습니다. 서버 패키지 전환은 앞서 설명한 별도 확인을 받습니다. 모델 선택은 Codex의 `/model`에서 합니다.
관리 세션은 명시적인 대화 ID를 지정한 일반 Codex 터미널을 사용합니다. 공유 서버 관리 방식은 CLI의 신구나 daemon 명령 유무가 아니라 필요한 보호 옵션으로 구분합니다. Core 연결은 공유 daemon을 사용합니다. 지원하지 않는 실행 파일은 세션 시작 전에 거부합니다. 외부 세션은 Core 프록시로 읽기 전용 관측합니다. 공유 서버 접속 실패나
미확인 상태를 명시하며 다른 서버를 자동으로 시작하지 않습니다.

창 닫기는 트레이로 숨기고, 앱 종료는 확인 후 앱이 소유한 프로세스를 종료합니다.
완전히 종료한 뒤 복원하면 저장한 대화 ID로 새 프로세스를 시작합니다.
앱 자체 SQLite에는 레이아웃·세션 메타데이터·프로젝트·실행 파일 선택을 저장합니다.
인증 토큰·터미널 대화록·Codex 인증 파일은 복사하지 않습니다.
언어 선택도 앱 자체 SQLite 설정에 저장하며 브라우저 미리보기만 localStorage를 사용합니다.

## 메모리와 기록 조회

필요할 때만 세션·대화를 한 페이지에 최대 50개씩 조회합니다. 화면에는 세션 목록 250개,
미리보기 메시지 100개·텍스트 128 KiB까지 유지하며, 더 불러오면 오래된 표시 페이지부터
비웁니다. 같은 세션을 다시 선택하면 최근 대화로 돌아갑니다. 팝업을 닫을 때 행·미리보기·
선택 정보를 해제하며, 대화 본문을 앱 데이터베이스에 복사하지 않습니다.
확장 관리 팝업도 처음에 50개 행을 표시하고 최대 250개 행을 유지하며, 닫을 때 조회한 데이터를 해제합니다.
터미널 입력은 처리 중인 요청을 포함해 최대 128개·256 KiB를 허용하며, 요청 하나의
크기는 기존 네이티브 제한인 64 KiB를 따릅니다. 대기량이 많으면 입력을 잠시 막고,
초과 입력은 알립니다. 크기 변경은 처리 중인 요청 하나와 최신 대기 크기만 유지합니다.
터미널 제거 시 대기 중인 입력·크기 참조를 해제하고, 저장된 세션은 처음에 메타데이터만 읽습니다.
터미널의 대화 이력과 모델 문맥은 선택한 CLI가 관리합니다. Desktop은 자체 표시·입력
버퍼에 상한을 적용하며, 이 제한이 CLI 프로세스 전체의 메모리 상한을 뜻하거나 대화 원본·
모델 문맥을 잘라내지는 않습니다.
상한과 객체 해제 시험을 장시간 메모리 누수 시험 완료로 표현하지 않습니다.
서버 요청의 응답·해결 기록은 세션마다 1,024개까지 보존합니다. 상한을 넘는 기록이
생기면 대화 관측과 입력 인계를 제한합니다. 해결된 질문이 늦은 알림으로 되살아나는
것을 막기 위한 제한이며, 원래 작업이나 대화 원본을 삭제하지 않습니다.

이전 Agent Grid의 설정과 등록 프로젝트는 유지합니다. Codex 실행 기반은
[Arcvera Core](https://github.com/jaeseongs95/opendiy-codex)입니다. 공식 Codex CLI는 지원하지 않습니다. 장기적으로 ChatGPT·Claude 데스크톱 앱의 기능과 사용성을 참고하되,
전체 벤치마킹과 더 넓은 기능 이전은 이후 작업입니다.

## 언어 선택

오른쪽 위 **⚙ 설정**을 열고 **언어**에서 **한국어** 또는 **English**를 선택하세요.
앱 화면과 앱이 지정하는 트레이·선택창 안내에 즉시 반영되며, 다음 실행에도 유지됩니다.
데스크톱 앱의 언어 선택값은 앱 자체 SQLite 설정에 저장하며 기본 언어는 한국어입니다.
세션 이름·경로·대화 내용·터미널 출력은 원문 그대로 표시합니다.
CLI 진단 메시지나 Windows 기본 버튼은 원래 언어로 표시될 수 있습니다.
CLI와 운영체제의 언어 설정은 바꾸지 않습니다.
