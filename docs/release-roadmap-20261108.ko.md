## 현재 우선순위 — 원격 연동 먼저

2026-11-08 후속 요청 “순차적으로 개발하고 릴리즈해줘.” 및 Remote 연동을 “먼저 해줄래?”에 따라 다음 순서로 변경한다.

| 목표 버전 | 항목 수 | 현재 배정 |
|---|---:|---|
| 1.7.0 | 3 | OpenDIY Remote 연결 UI·호스트 어댑터(T0073), 실물 모바일 검증(T0061/C0008). 실제 휴대전화 증거는 합성 CI와 분리한다. |
| 1.7.1 | 58 | 당초 1.6.5에 배정한 잔여 안정화·기존 기능 검증. 이미 완료한 후보 구현·시험을 재구현하지 않는다. |

1.6.5(5e42056)는 내부 검증 후보로 보존한다. 신규 기능을 포함한 다음 공개 후보는 SemVer에 따라 1.7.0이다. 버전 이동은 결함 종결이나 수용조건 완화를 뜻하지 않는다. 상세 현재 배정은 `verification/remote-integration/version-plan-priority.json`이며, 아래는 변경 전 계획의 이력을 보존한다. 기존 1.6.4 자산·설치본을 덮어쓰지 않는다. 검증 뒤 필요한 병합·태그·GitHub 릴리스는 사용자 요청으로 승인됐고, 설치·운영 배포는 별도다.

## 최초 배정 기록

기준: 2026-11-08 장부 직접 조회. 사용자 요청: “지금 장부에 있는것들 다 처리해야하는것들이잖아. 너가 어떤걸 어느 버전에 올릴지 계획 세우고 진행해.”

현재 공식 최신은 1.6.4다. 서버 선택 후보 74c4c19/PR6는 아직 1.6.4로 빌드된 작업 후보이므로 첫 신규 배포 대상은 1.6.5로 올린다. 동결 1.6.4 태그·공개 자산·설치본을 덮어쓰지 않는다.

미완료 작업 22개, 미해결 결함 32개(OPEN22/SOURCE_FIXED10), 미확인 수용조건 14개, 합계 68개를 아래에 한 번씩 배정했다. VERIFIED 작업 53개·결함 23개는 재구현 대상에서 제외하고 회귀·근거로 보존한다. 68개는 새 기능 개수가 아니며 기존 수정의 검증·시험기 결함·상시 작업·수용조건을 포함한다. 전체 상태는 조회 당시 값을 유지한다.

| 목표 버전 | 주제 | 항목 수 | 내용 |
|---|---|---:|---|
| 1.6.5 | 서버 전환·안정성·기존 기능 마무리 | 58 | 서버 선택 교체(PR6), 시작 지연·입력·컨텍스트 사용량의 원인 분리, 이미 반영된 기능의 근거 대조, 시험기·설치/업데이터 검증의 신뢰성 보완. 원인 미확인 항목은 먼저 판별하고 확인한 결함만 수정한다. |
| 1.7.0 | UI/UX 전면 개편 | 4 | 정보 구조·주요 작업 동선·상태/오류 표시·접근성·좁은 화면을 개편하고 다크/라이트/시스템 테마와 설정 보존을 구현한다. 기존 하단 도구 재배치와 실제 질문 입력 경계를 함께 마무리한다. |
| 1.7.1 | 장시간 성능·자원 안정화 | 3 | 1.6.5 기준선과 1.7.0 변경 후를 같은 부하로 비교한다. 실제 타이핑·전환 지연, 메모리·연결·프로세스 추이와 누락을 구분하고 확인된 병목을 개선한다. |
| 1.8.0 | 원격 연결·실물 모바일 | 3 | Desktop의 relay 연결 설정·상태 UI·호스트 SSE 어댑터를 구현하고 물리 휴대전화 페어링·조회·제어·해제·권한을 검증한다. 실제 비밀 입력과 실물 조작이 필요한 단계는 따로 남긴다. |

목표 버전은 구현·검증을 끝낼 순서이며 지금 배포·설치했다는 뜻이 아니다. 원인 미확정 항목의 조사 결과나 확인된 의존성이 달라지면 해당 ID의 배정 변경 이유와 남은 범위를 장부에 기록한다.

SemVer를 따른다. 1.6.5와 1.7.1은 기존 동작의 결함·성능 수정이며, 새 테마·화면 개편은 1.7.0, 새 원격 연결은 1.8.0에 넣는다. 기존 계약을 깨는 변경은 이 계획에 포함하지 않는다. D0014/D0015의 과거 심각도 UNRATED는 현재 장부의 유효 코드가 아니므로, 데이터 손실·보안 침해가 확인되지 않은 시작/시험 신뢰성 결함으로 P2를 부여하고 원 분류를 이력에 보존한다. 결함 상태 OPEN은 그대로 유지한다.

## 진행 순서와 검증

1. 1.6.5: 기존 소스·검증 근거를 대조하고 원 실패를 보존한다. 사용자가 선택한 서버 교체를 첫 실행 대상으로 삼아 제품 버전을 1.6.5로 올리고 CI에서 새 후보를 만든다. 컨텍스트 사용량은 현재 읽기 계약부터 확인하며 없는 API를 추정하지 않는다. 시험기 오판은 제품 결함과 분리해 고친다.
2. 1.6.5: 취소/action join, 정확 프로세스 세대·경로·실행 역할·native 오류 원문·잔류 회수의 관측을 보강한다. 기존 수정 10건은 코드·회귀·실제 근거가 연결된 범위만 종결 후보로 올린다. 권한 없는 VERIFIED 전이는 시도하지 않는다.
3. 1.7.0: 디자인 시스템과 다크/라이트/시스템 테마를 먼저 적용한 뒤 주요 화면·설정·세션·질문 동선을 개편한다. 기존 권한·MCP·예약·업데이트·서버 선택의 실패/미확인 경계를 보존한다.
4. 1.7.1: 1.6.5부터 수집한 기준선과 개편본을 같은 조건으로 비교한다. 짧은 PTY 자체 시험·모의 이벤트를 장기 누수 해결이나 실제 IME 성공으로 승격하지 않는다.
5. 1.8.0: 원격 담당의 정본 계약을 확인해 Desktop의 연결 UI와 어댑터를 구현한다. 물리 기기·실계정·실제 비밀이 필요한 검증은 도구·단위 시험과 분리한다.

각 버전의 수용 기준은 해당 행의 장부 원문과 `verification/release-plan-20261108/version-plan.json`에 보존한다. 사례를 먼저 정의하고 실제 실패 경계의 red/green·원시 결과·후보 해시·최종 업무 단위 독립 감사를 연결한다. 장부 배정은 완료 상태 변경이 아니다.

## 공통 경계

- 공동시험·ponytail·로컬 Rust 제품 빌드를 실행하지 않는다. 기존 동일 후보 근거 검토와 새 실행을 구분한다. Rust 빌드·검증은 CI를 사용한다.
- 운영 daemon/PID·인증·DB·진행 중 작업·타 세션 원시 대화/개인로그를 건드리지 않는다.
- 작업 브랜치 편집·commit/push·CI는 진행한다. 기본 브랜치 병합·태그/릴리스·설치/배포·영구 삭제·권한 확대·운영 데이터 변경은 별도 승인 경계를 유지한다.
- T0029/T0031과 C0001/C0003/C0006/C0013/C0014는 1.6.5부터 매 버전 공통이다. T0032는 사용자 지시대로 불가능한 경우 제품 작업의 차단 조건으로 삼지 않는다.
- C0002의 옛 “경로 선택만으로 바꾸지 않음”은 최신 T0074의 명시 선택 교체 요청에 맞춰 정정한다. 선택 교체와 별도 수동 비강제 전환을 구분하며 응답 불명 자동 반복은 계속 금지한다.
- T0073/T0075의 과거 “등록·요구 확인만” 표기는 이번 전 항목 진행 요청으로 구현 계획에 포함한다. 서버 운영·비밀·공개 권한을 확대한 것은 아니다.
- T0026/T0068 등 기존 실행·공개·설치 근거는 우선 대조해 오래된 미완료 표시와 실제 잔여 범위를 구분한다. 미검증 부분까지 완료로 올리지 않는다.
- 현재 PR6에는 취소한 중복 push의 실패 체크가 남는다. 성공한 PR CI와 구분해 후속 후보에서 실제 검증 결과를 확인한다.
