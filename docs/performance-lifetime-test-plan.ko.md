# 대화 화면 자원 수명 시험 계획

Arcvera-Studio1.8.0 이후 T62의 첫 검증 단위이다. 생성한 이력으로 기존 대화 화면을 측정한다. 이 시험만으로 T62 완료 또는 실제 앱의 누수 수정을 선언하지 않는다. Rust 구현을 유지하며 Java 전환은 진행하지 않는다.

제품 기준 소스는3460042da2024c7a3ecbdcead1655c98bbf06241이다. 기존 Playwright/Chromium 소스 fixture에서 worker1개, 브라우저1개,1440×1000 화면을 사용한다. RPC fixture는 페이지마다 고유 메시지100개를 생성하고, 누적 호출 기록 대신 계수만 보존한다. 인증 정보·사용자 대화·운영 서비스를 사용하지 않는다.

| 사례 | 검증 경계와 판정 기준 |
| --- | --- |
| CR01 | 이력 교체와 화면 전환을24회 반복한다. 표시 행100개, 백그라운드 행0개, 동일한 한글 초안 보존과 이력 재조회49회를 확인한다. |
| CR02 | controller16개를 생성·종료하고 host를 제거한 뒤 CDP로 명시적 GC를 실행한다. 약한 참조32개가 모두 해제되고 실제 polling 주기를 지나도 polling이 멈춰 있어야 한다. 격리된 응답 변이에서 실제 언어 구독 해제를 누락하면 동일한 회수 assertion이 실패해야 한다. |
| CR03 | 선택 실행으로 세션4개의 화면을 계속 전환한다. 동일 페이지의 실행 세대, 고정 부하, UTC·단조 시각, 필수 heap·작업 시간·DOM 계수를5초마다 기록한다. 예정 표본과 요청 시간을 모두 채워야 하며, 필수 수치 누락 또는5초 이상의 표본 지연은 실패한다. 실패 시에도 부분 JSONL과 완료·오류 요약을 보존한다. |

실행 명령은 `npx playwright test tests/conversation-resource.spec.ts`이다. `RESOURCE_LIFETIME_SOAK_SECONDS`가 없으면 CR03은 건너뛰며, 이를 통과로 세지 않는다. 지속 시험은10..14400초로 지정한다. 전용 Windows workflow는 작업 브랜치 push에서30초, 수동 dispatch 기본값으로1800초를 실행한다. 실패해도 원시 artifact를 업로드한다. heap·DOM 추이는 관측 결과이며 임의의 누수 통과 한계를 만들지 않는다. 명시적 GC는 CR02에만 적용하고 CR03은 정상 GC 상태를 측정한다.

원래 T62 수용조건인 동일 실행 세대·부하 조건·측정 누락을 구분한 장기 부하 전후 자원 추이와 회귀 평가는 유지한다. 실제 WebView·CLI·프로세스와 연결 수명·물리 IME·수 시간 앱 사용은 격리된 Windows 환경의 별도 근거가 필요하다. 짧은 Chromium 시험·빌드·감사 통과만으로 해당 결과를 인정하지 않는다. 이번 작업에서 설치나 릴리스는 수행하지 않는다.
