# 1.6.1 네이티브 바이너리 입력 사례

실행 전 작성. FCS02 당시의 xterm 마우스 encoding은 미확인이다. 이 사례는 확인된 DEFAULT/onBinary 전달 누락과 실제 바이트 경계를 검사하며, FCS02 해결을 대신하지 않는다.

| 사례 | 전제·입력·절차 | 기대값·실패 기준 | 실제 결과 |
|---|---|---|---|
| NB01 | xterm byte-string의 모든 값 0x00..0xff를 네이티브 binary 변환 경계에 전달한다. | 정확히 256바이트, 각 값 불변. UTF-8 확장·교체·손실이면 실패. | NOT_RUN |
| NB02 | byte-string 길이 65536과 65537을 각각 전달한다. | 전자는 원본 65536바이트, 후자는 기존 64KiB 오류. 한도 초과 입력은 PTY에 전달하지 않는다. | NOT_RUN |
| NB03 | binary 입력에 한글 또는 U+0100을 섞는다. | Latin-1 바이트로 표현할 수 없는 입력은 명시적으로 거부하며 잘라내거나 UTF-8로 보내지 않는다. | NOT_RUN |
| NB04 | 없는 세션/종료된 세대에 binary 입력을 보낸다. | 일반 입력과 동일한 소유권·세대·생존 검사에서 거부한다. | NOT_RUN |
| NB05 | 실제 xterm DEFAULT와 SGR 클릭, UTF-8 키 입력을 한 직렬 큐에 넣는다. | binary/text 표시와 원래 순서를 보존한다. 프로젝트·세대 변경과 queue 한도는 기존 정책을 유지한다. | 별도 browser 사례에 기록 |

Rust 사례는 실제 PTY의 CLI parser 소비를 증명하지 않는다. 최종 WebView/ConPTY 클릭과 부모·하위 왕복, 초안·대기열 시험은 별도로 남긴다.
