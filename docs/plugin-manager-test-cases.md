# 플러그인 관리 개편 사전 테스트케이스

사용자 지시: 관리창 기본 화면에서 모든 플러그인을 보여주지 않는다. 설치된 항목 관리와 새 항목 찾기를 구분한다.

| ID | 입력·사전조건 | 기대 결과·통과 기준 |
| --- | --- | --- |
| PM01 | 관리창 처음 열기·기본 새로고침 | 설치된 항목만 조회·표시하며 CLI `plugin list --available`을 실행하지 않음 |
| PM02 | 플러그인 추가 진입, 아직 검색하지 않음 | 전체 카탈로그가 자동으로 로드·표시되지 않음. 이름 검색 안내 |
| PM03 | 명시한 검색어로 찾기 실행 | 선택 CLI/프로젝트를 유지해 실제 카탈로그를 조회하고 검색 결과만 표시 |
| PM04 | 검색 결과에서 설치 검토·확인 | 검토 전 설치하지 않음. 정확한 selector로 설치·read-back 후 설치된 항목 관리로 복귀 |
| PM05 | 검색 중 다른 탭/프로젝트·닫기·지연 응답 | 오래된 검색이 현재 관리 목록이나 선택 대상에 누수되지 않음 |
| PM06 | CLI 검색/설치 실패·미지원 | 빈 성공이나 설치 완료로 숨기지 않음. 설치 항목 관리와 Hook·스킬·기본 세션 기능 유지 |

기존 CLI/RPC 및 admission·목록 DOM 상한·검토 확인 흐름을 재사용한다. 새 카탈로그 서비스나 임의의 plugin 업데이트 명령은 만들지 않는다.

2026-11-04 통합 Playwright 실행의 extensions 18개는 모두 통과했다. 첫 실행의 2개 실패는 제거 후 미설치 카탈로그를 기본 관리 화면에 남기거나 전체 목록을 기대하던 기존 assertion이었다. 설치 목록이 비고 명시 검색에서만 다시 설치 가능해지는 새 요구로 사례를 보강했다. 첫 실패 trace는 `artifacts/hooks-plugin-playwright`에 보존했다. 실제 CLI/Rust/GUI 검증 범위와 구분한다.
