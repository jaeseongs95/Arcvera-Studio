# 네이티브 PTY 자원 관측

이 T62 검증 단위는 공개된 v1.8.0의 기존 headless 자체 시험을 격리된 Windows CI 한 작업에서 실행한다. 앱을 설치하지 않는다. 실행 파일의 소스는 `3460042da2024c7a3ecbdcead1655c98bbf06241`이며 크기는 16,093,184바이트, SHA256은 `60ef6aeda944b6ba65baa14c5124c4d04abe2e25df7a1e2a087ce232534aeb49`이다.

구현과 실행 전에 작성한 사례:

| 사례 | 실제 경계와 판정 기준 |
| --- | --- |
| NR01 | 공개 릴리스 실행 파일을 작업 전용 출력 폴더로 내려받고, 실행 전에 크기와 SHA256을 정확히 대조한다. |
| NR02 | `--self-test --duration-seconds 1800 --report <전용폴더>/self-test.json`을 실행한다. 종료 코드 0, 반복 수 양수, 보고된 시험 전부 통과, 오류 없음, 실행 시간 1800초 이상을 확인한다. 기존 시험은 격리·정리 확인과 생성·정지 100회 뒤 동일한 PTY 8개로 장기 heartbeat를 수행한다. |
| NR03 | 5초마다 실행 ID·PID·생성 시각·단조 경과 시간·메모리·핸들·CPU 시간을 원시 JSONL에 추가한다. 361개 이상 표본, 누락 없음, 표본 간격 15초 이하가 필요하다. 실패해도 부분 JSONL과 요약을 보존한다. 추이는 기술 통계로 보고하며 임의의 누수 통과 기울기를 만들지 않는다. |
| NR04 | 마지막 소유 Job 프로세스 수 1과 기존 프로세스 트리 보고서의 각 fixture 종료 신호를 확인한다. 정상 종료는 앱의 기존 정리를 사용한다. 기한 초과·오류 시 래퍼가 직접 시작한 프로세스 핸들만 종료하며, 앱의 kill-on-close Job이 자손을 소유한다. 전체 프로세스 조회·종료는 하지 않는다. |

시작 전 메모리·디스크 여유를 확인한다. 작업은 하나이며 CI 제한 시간은 260분, 래퍼 기한은 요청 시간에 15분을 더한 값이다. 프로세스 생성 구간은 공유 2코어 시험 서버 대신 격리 CI에서 실행한다. 근거는 14일간 보존한다. 워크플로 커밋과 실행 파일의 소스 커밋을 구분한다.

앱 자체 보고서는 약 30초마다 소유 Job 수를 기록한다. 외부 5초 표본의 메모리는 실행 파일 자체의 값이며 자손 전체의 합이 아니다. 앱의 첫 내부 표본은 Job 설치 전이므로 소유 프로세스 수가 누락될 수 있고 이를 그대로 보존한다. 이후 내부 표본에는 모든 네이티브 자원 값이 있어야 한다. 누락을 0으로 해석하지 않는다.

이 자체 시험은 Tauri/WebView를 초기화하지 않고 합성 PTY를 사용한다. GUI 타이핑·채팅 전환, 실제 CLI·공급자 연결, 물리 IME, 수 시간 네이티브 앱 사용, 설치·업그레이드는 미검증이다. 관측 통과만으로 제품 결함이나 수정 효과를 주장하지 않는다. [영문판](native-resource-observation.md).
