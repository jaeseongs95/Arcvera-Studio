# 네이티브 CLI 시작 시험 사례

대상은 공개 v1.8.0 앱(소스 `3460042da2024c7a3ecbdcead1655c98bbf06241`), 공식 Codex CLI 0.166.0 및 일회용 Windows CI다. 실행 전에 정의한 사례다. [English](native-cli-cases.md).

- NC01: 공개 앱의 SHA-256·크기와 네이티브 CLI SHA-256을 대조한다. 불일치하면 실행 전에 실패한다. 선택한 CLI 옆에 `codex-app-server.exe`가 없어야 한다.
- NC02: 인증·Codex 홈·프록시·CLI 선택을 유입할 수 있는 레지스트리 환경변수 이름이 있으면 중단한다. 새 결과 폴더와 HOME·USERPROFILE·CODEX_HOME을 만든다. 자식 환경을 비우고 OS 경로와 격리 설정만 명시한다. 기존 사용자 파일은 읽지 않는다.
- NC03: 격리 환경에서 두 도움말을 조회하고 설치 보호 옵션이 모두 없는지 확인한다. 데몬 시작·설치는 하지 않는다. 이후 `--codex-smoke --sessions 1 --report <path>`만 실행한다. 터미널 진단 원문·사용자 입력·엔진 제어·모델 요청은 사용하지 않는다.
- NC04: 종료 코드 0, 예상 보고서 형식과 신규 시작 모드, UUID에 결속된 세션 1개, 비어 있지 않은 PTY 바이트, 빈 오류, 메모리 계측 및 최종 소유 프로세스 수 1을 요구한다. 인증·신뢰 안내는 답하지 않고 시작 실패로 보존한다.
- NC05: 도움말은 각 20초, 시작 시험은 150초로 제한한다. 직접 만든 프로세스의 식별·종료 코드·강제 정리 여부를 기록하고 그 트리만 종료한다. 실패해도 부분 근거를 보존한다.

기존 시작 시험의 결속·정상 정리 검사를 재사용하며 제품 변경이나 변이 검증을 주장하지 않는다. 제한시간 정리는 정상 정리 성공이 아니다. GUI·물리 IME·입력 지연·실제 CLI 장기 안정성·누수 부재·T62 전체 수용은 별도다. 공유 Windows TEST 환경의 레지스트리 격리가 충분하지 않아 일회용 CI를 사용한다.
