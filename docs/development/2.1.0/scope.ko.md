# Desktop 2.1.0 개발 범위와 공동 검증 초안

2026-11-14 KST. 사용자 목표: “너의 목표는 2.1.0 릴리즈이다. cli 담당과 협업해서 2.1.0 릴리즈에 들어갈 개발 범위를 산정하고 작업하면 된다.”

3.x 개발은 중단하고 기존 작업본과 미검증 변경을 보존한다. 이 작업은 현재 Rust/Tauri Desktop과 Rust Core의 연동을 대상으로 한다. Java 3.x 코드나 제안된 Core HTTP/SSE 계약을 이 릴리스에 섞지 않는다.

기준 Desktop은 공개 2.0.1의 `beb6fe54c160d04d01d57c04c305c2fc519f9490`이다. 작업 브랜치는 `feature/desktop-2.1.0-core110`이다. 2026-11-14 KST 조회한 원격 main은 2.0.0의 `0fa0f9c2da3f832db9d01cb7b0f00ddec90a538a`이므로, 2.0.1의 버전 접두사·최초 준비 호환 수정을 보존한다. 최종 병합 때 원격 main을 다시 확인한다.

Core 담당 작업은 `D:/codex/build/core110-context-20261113/source`, `feature/1.1.0-context-runtime`, 기준 `d6026cbd`이다. 현재 개발 실행 파일은 전달되지 않았다. 아래 범위와 오류·적용 계약은 CLI 담당과 대조 중이며, 실제 지원으로 확정하거나 시험 통과로 표시하지 않는다.

기존 T78은 전용 context_index UI를 요구하지 않는다. 실제 handler/wire/live/history 전달과 필요한 Desktop 변경 여부를 확인한다. T62의 전체 장시간 부하는 미완 이월임을 유지하고, 이번 변경이 영향을 주는 연결·대기열·화면 응답·회수 경계의 실제 검증을 수행한다. 한쪽 단위시험이나 합성 응답만으로 양쪽 제품의 사용 가능성을 판정하지 않는다.

수용 기준:

- AC-001: CLI 담당과 기능·wire·적용 범위·미지원/결과 불명 의미 및 같은 시험 fixture를 합의한다.
- AC-002: S01~S05의 정상·실패 경계를 동일한 Core/Desktop 후보 짝으로 실제 실행하고, 관측된 결과를 상태·표시와 대조한다.
- AC-003: 기존 인증·설정·사용자 데이터·진행 작업·다른 세션을 보존하며, 테스트는 자체 HOME/프로젝트/임시 파일과 자체 프로세스만 사용한다.
- AC-004: 표적 회귀·실제 통합 검증 이후 최종 패키지를 빌드하고, 정확한 후보의 CI와 라이선스·영한 문서를 확인한다. 최종 변경과 증거는 구현자와 분리된 감사자가 확인한다.
- AC-005: 별도 승인된 공개 단계와 사후 검증을 마친 뒤에만 릴리스 완료로 보고한다. 남은 미검증 사항은 숨기지 않는다.

작업 브랜치 편집·개발 의존성 설치·시험·commit/push·CI는 배정된 개발 범위에서 진행한다. 기본 브랜치 병합·tag/release·설치/배포·영구 삭제·권한 확대·운영 데이터 변경의 별도 승인 경계는 유지한다. CLI 담당의 빌드 예약·goal 제어 지시는 이 세션의 별도 사용자 승인으로 간주하지 않는다.

이 문서는 범위 협의와 수용 기준의 작업 원문이다. 기계용 TaskEnvelope/검증기 통과 또는 제품 완료 판정으로 표현하지 않는다.

CLI 담당과 컨텍스트 구성 조회를 협의 중이다. fragment ID·인덱스/출처·선택 이유·필수 여부·크기·prefix 순서·활성/회수 상태, 캐시 정책/관측/추정/미제공 구분을 소비 필드로 제안했다. 개별 fragment와 전체 prefix의 캐시 관측 범위를 혼동하지 않고, 원문·secret은 기본 표시 자료에 포함하지 않는다. 정본 schema·한도·snapshot 일관성 계약이 확정되기 전에 임의 RPC를 구현하지 않는다. 현재 전용 구성 조회는 미구현·미검증이다.
