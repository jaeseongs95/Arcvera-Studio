# 앱 서버 선택 교체 사례

요청: 새 앱서버 선택은 기존 공유서버 종료 후 선택 서버를 시작한다. 서버 이름으로 일괄 종료하지 않고 CLI가 소유한 공유서버 관리 명령을 사용한다. 공동시험은 하지 않는다.

1. 새 경로 선택: 저장 후 교체용 preview → 강제 종료 허용 전환 → 실제 선택 서버 확인. 설정창을 닫아도 이미 선택한 전환은 정산한다.
2. 취소: 전환 명령 0회. 같은 경로라도 파일이 바뀌었거나 이전 선택이 적용되지 않았을 수 있으므로 사용자가 다시 선택하면 교체한다. UI 중복 클릭은 진행 잠금으로 1회만 받는다.
3. 교체 실패/응답 불명: 성공 문구와 자동 재시도 없음. 선택 경로 및 실패를 표시한다.
4. 중복 클릭/닫기 후 재열기: 전환은 1회이며 진행 중에는 선택을 잠근다.
5. CLI 지원/패키지 부재: 종료 전 실패. bare EXE 3개는 관리 CLI의 완전패키지에 3개 모두 SHA256이 동일한 경우에만 그 완전패키지를 재사용한다. 버전 문자열만 같은 다른 바이트는 거부한다. 잘못된 manifest를 만들거나 다른 실행본으로 대체하지 않는다.
6. 기존 수동 비강제 전환: --no-force와 명시 확인 계약을 보존한다. 선택 교체만 기본 grace 후 force 정책을 사용한다.

검증: 기존 Playwright 설정창/전환 시험에 사례를 먼저 추가하고 수정 전 실패→수정 후 같은 사례를 실행한다. 프로세스/패키지 경계 Rust 단위 시험은 CI에서 수행한다. 로컬 운영 daemon과 공동 GUI 시험은 실행하지 않는다. 모의 IPC 검증은 실제 서버 교체 검증으로 보고하지 않는다.

CS 불변조건: runtime.changing 동안 선택과 새 시작을 거부한다. 외부 명령 동안 runtime/store 잠금을 보유하지 않는다. 응답 불명은 실패 경계를 보존하고 자동 반복하지 않는다. 선택 세대가 달라지면 전환을 실행하지 않는다.
