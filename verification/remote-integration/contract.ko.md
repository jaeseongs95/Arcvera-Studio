# 원격 연동 우선 구현 계약

사용자 원문: “순차적으로 개발하고 릴리즈해줘.” 이어서 “https://github.com/jaeseongs95/opendiy-remote <- 이거 붙이는건 어떻게 되고있는거야?”, “먼저 해줄래?”, “중단된 지점부터 이어서 작업해줘.”

사용자는 Desktop 설정에서 자신의 중계기에 연결하고 외부 브라우저에서 같은 Desktop의 세션을 제어한다. 다음 기능 릴리스는 1.7.0이다. 기존 1.6.5는 내부 후보로 보존하고, 잔여 안정화는 1.7.1, UI는 1.8.0, 장기 성능은 1.8.1 순으로 진행한다. 운영 설치·중계기 배포·인증 변경은 포함하지 않는다.

정본: opendiy-remote 56c1968cbdc1626005993f1dc32f64d936c10f00의 server/remote-server.mjs(blob53cd2173eae7c4cd33e736c56a54311c5bc9d82e) 및 docs/relay-protocol.md. 문서의 명령 40개/이벤트4개 표기는 소스의47개/5개와 다르므로 실제 소스 목록에 결속한다.

설계: Rust의 별도 relay 전송 모듈에서 기존 Tauri 명령 함수를 호출하는 어댑터로 연결한다. 별도 Node 런타임·별도 세션 서버는 만들지 않는다. 기존 native_worker, 설치 중 동작 차단, Engine의 세대·권한·질문 응답 검사를 재사용한다. 원격 경로 입력만 네이티브 파일 창 대신 명시 경로 검사를 사용한다. 이것은 실제 전송·권한 경계의 분리이며 업무 로직을 복제하지 않는다.

CS 불변조건(CONC-CANCEL-004, DIST-IDEMPOTENCY/RESOURCE 경계): 연결 해제는 새 원격 명령 수락과 재접속을 중단하고 네트워크 task를 abort 후 join한다. 이미 수락된 Engine 명령의 부작용은 취소됐다고 주장하지 않는다. 연결 세대가 다른 결과·이벤트는 새 연결에 게시하지 않는다. 최근256개/16MiB 응답 캐시와4개/16MiB 진행 요청,4MiB 이벤트 큐를 제한하며 중복 reqId는 재실행하지 않는다. 초과/프로토콜 오류는 성공이나 무음 유실로 바꾸지 않는다.

수용 사례(구현 전에 작성):

- AC-01: URL wss→https/ws→http 정규화, 비루프백 평문·사용자정보·잘못된 스킴 거부, redirect 금지. 실제 registered와1.0.0/hostId 확인 뒤에만 연결됨 표시.
- AC-02: HostSecret은 입력 후 지우고 메모리에만 유지한다. 파일/상태/오류에 노출하지 않는다.401/403/409/429는 자동 재시도하지 않는다.
- AC-03: 정본47개 명령은 기존 명령/경로 검사에 대응하고 종료·실행파일변경·OS창 호출은 차단한다. 기존 세대·단일응답 검사를 유지한다.
- AC-04: 분할UTF8/SSE·주석·다중data·잘못된JSON·상한, 진행/완료 중복reqId, 연결끊김/재접속/명시해제/오래된세대와 큐·캐시 상한을 시험한다.
- AC-05: 설정 진입→주소/비밀 입력→연결 대기→상태→해제와 오류/중복클릭/IME/키보드·좁은창을 기존 Playwright로 확인한다. native는 Windows CI에서만 실행한다.
- AC-06: 업무단위 fresh 독립감사 후 검증된 산출물을 릴리스한다. 실제 운영 중계기/실물 휴대전화는 별도 증거로 유지하고 합성 시험을 실물 성공으로 부르지 않는다.

제약: 공동시험·ponytail·로컬Rust·운영daemon/auth/DB·타세션 개인로그 금지. 동결1.6.4와 진행 작업 보존. 구현자 직접 작업, 감사만 독립 worker. 기존 D0053 CI42477403292는 retain-process-handle 변이가 살아남아 FAIL이며 수정 전 실패 근거를 보존한다. 이 결과로 역사 원인을 확정하지 않는다.
